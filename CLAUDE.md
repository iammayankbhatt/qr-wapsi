# QR Wapsi — project context for Claude Code

Read this file fully before doing anything. It is the single source of truth for this project.

## What we are building

QR Wapsi is a hackathon prototype for the **Paytm Build for India AI Hackathon (Delhi), Track 3: Autonomous AI Teammates**, by **Team Hawks** (Mayank Bhatt, Bhumika Bhatt, Tanuja Kanswal).

**Problem.** RBI's Payment Aggregator Directions (Sept 2025) require aggregators like Paytm to bring every merchant onboarded till 31 Dec 2025 up to new due-diligence norms. Small merchants who are not paused today risk payment pauses if not re-verified. For small merchants (turnover ≤ ₹40 lakh, not found in CKYCR) the route is: PAN or Form 60 verified with the issuing authority, one officially valid ID document (OVD), and a Contact Point Verification (CPV) — a physical check of the shop. The bottleneck is field capacity: in-person checks are done by the aggregator's own staff.

**Solution.** An AI teammate that clears the re-KYC backlog end to end:
1. **Triage** — ranks paused merchants by value at risk, missing documents and mule-risk signals, and explains why.
2. **Collect** — contacts the shopkeeper in Hindi (Soundbox voice + WhatsApp-style chat), collects documents, checks them, asks for fixes.
3. **Schedule** — books the field visit in the shop's quiet open hour (from payment timestamps) and routes the employee's day.
4. **Verify** — a field employee does the in-person check in a pre-filled field app.
5. **Reactivate** — a deterministic rules engine checks every requirement, seals an audit record, the QR goes live and the Soundbox says "Aapka QR phir se chalu".

## The one demo that must work perfectly (finale script)

1. Dashboard shows 1,000 paused merchants. The agent picks **Sharma Kirana Store** (the hero merchant) as top priority and shows why it ranked first.
2. In the shopkeeper phone simulator, the agent sends a Hindi WhatsApp message and plays a Hindi Soundbox prompt. The shopkeeper uploads a **blurry PAN specimen** → rejected with a specific fix ("photo is blurry, please retake in good light") → uploads the **sharp specimen** → accepted.
3. The agent books a **3:10 PM** visit (the shop's quiet hour) and adds it to today's field route.
4. In the field app, the employee does the in-person check (geo-tag, signboard photo, confirm). The rules engine shows each requirement passing.
5. Audit record sealed → QR status flips **Paused → Live** → Soundbox plays "Aapka QR phir se chalu".

Everything else is secondary. Never break this path.

## Hard rules (do not violate)

- **The LLM never decides compliance.** Only `rules_engine.py` (pure Python, no LLM) can mark a merchant compliant. The LLM proposes actions, writes messages, explains rankings and extracts document fields. Every LLM output is validated with Pydantic; invalid or low-confidence output falls back to a deterministic policy.
- **The in-person verification (CPV) is never skipped or automated away.** Only a field-employee action can satisfy `CPV_DONE`.
- **All data is synthetic.** No real names of real people, no real PAN numbers. Specimen document images are generated by our script and visibly watermarked "SPECIMEN — DEMO ONLY". Show a small "Prototype · synthetic data · integrations simulated" banner on every screen.
- **Simulated integrations sit behind real-looking interfaces**: CKYCR lookup, PAN verification with the issuing authority, DigiLocker, WhatsApp, IVR, Soundbox device and Paytm payment data are all mocks in `backend/app/integrations/`, each a class with the same method names a real client would have.
- **Demo mode must work offline.** With `DEMO_MODE=replay`, every LLM and TTS call is served from `backend/demo_cache/`. The finale demo must run even if Wi-Fi or an API fails.
- Keep it simple. No Docker, no auth, no Kafka, no Postgres. Prefer boring, reliable code over clever code.

## Tech stack

**Backend** — Python 3.11+, FastAPI, Uvicorn, SQLModel on SQLite (`backend/data/app.db`), Pydantic v2.
- **Agent:** LangGraph `StateGraph`, one thread per merchant (`thread_id = merchant_id`), checkpointed with `langgraph-checkpoint-sqlite` (`SqliteSaver`, file `backend/data/checkpoints.db`). Use `interrupt()` to pause while waiting for the shopkeeper or field employee and `Command(resume=...)` to continue.
- **Tools over MCP:** tools are defined once in `backend/app/tools/` and exposed by an MCP server (`backend/app/mcp_server.py`, using `mcp.server.fastmcp.FastMCP`). The agent calls them through `ToolClient`, which has two transports: `mcp` (stdio client session to our MCP server, default) and `direct` (in-process call, fallback). Choose with env `TOOL_TRANSPORT`. If MCP fails at startup, log a warning and fall back to `direct` automatically.
- **LLM:** Google Gemini via the `google-genai` SDK (`from google import genai`). Model from env `GEMINI_MODEL` (default `gemini-3.8-flash`, fallback `GEMINI_FALLBACK_MODEL=gemini-3.5-flash-lite`). Use structured output (`response_mime_type="application/json"` + `response_schema` with a Pydantic model). All LLM access goes through one module, `backend/app/llm.py`, which handles retries, timeouts (15 s), fallback model, JSON validation and the demo cache.
- **Document AI:** Gemini vision for extraction (doc type, name, PAN number, confidence) + local checks: blur via Laplacian variance (OpenCV or Pillow+NumPy), PAN regex `^[A-Z]{5}[0-9]{4}[A-Z]$`, name match with `rapidfuzz`.
- **Voice:** Sarvam text-to-speech, `POST https://api.sarvam.ai/text-to-speech`, header `api-subscription-key`, body `{text, language_code: "hi-IN", model: "bulbul:v3", speaker: "priya"}`, response field `audios` = list of base64 WAV. Cache every generated clip in `backend/demo_cache/audio/`. Fallback: the browser's `speechSynthesis` with `hi-IN`.
- **Routing:** Google OR-Tools (`ortools`) for one employee's day, with time windows around each shop's quiet hour.
- **Real-time UI updates:** Server-Sent Events (`/api/events`).
- **Tests:** pytest.

**Frontend** — React + Vite + TypeScript + Tailwind CSS. `react-router-dom` for pages. No component library needed; build clean cards. Charts with plain SVG or `recharts`.

**Brand** — navy `#0E1B3D`, amber `#F2A93B` (action), teal `#13A39A` (live/success), red `#E5484D` (paused), light panel `#F1F4F9`. Headings serif (Cambria/Georgia), body sans (Inter/system). Must look professional on a projector: large text, high contrast.

## Environment variables (`.env`)

```
GEMINI_API_KEY=
GEMINI_MODEL=gemini-3.8-flash
GEMINI_FALLBACK_MODEL=gemini-3.5-flash-lite
SARVAM_API_KEY=
DEMO_MODE=live            # live | record | replay
TOOL_TRANSPORT=mcp        # mcp | direct
```

`record` = call real APIs and save every response to `demo_cache/`; `replay` = never call external APIs, serve from cache (fail loudly in logs, then use a deterministic fallback, if a cache entry is missing).

## Data model (minimum)

- **Merchant:** id, shop_name, owner_name (synthetic), category, city (Noida/Delhi NCR), lat, lng, turnover_band, in_ckycr (bool), qr_status (`PAUSED`|`IN_PROGRESS`|`LIVE`|`ESCALATED`), has_soundbox, monthly_gmv, subscription_per_month, has_active_loan, hourly_txn_histogram (7×24 counts), open_hours, risk_features (payer_diversity, spike_ratio, round_amount_share, night_share), docs_status.
- **Journey:** merchant_id, current_step, priority_score, priority_reasons (list), mule_risk_score, visit_slot, assigned_employee, attempts (per channel), escalation_reason, timestamps.
- **Document:** merchant_id, doc_type (PAN|FORM60|OVD), file path, extracted fields, quality metrics, decision (ACCEPTED|REJECTED), reason, attempt_no.
- **Visit:** merchant_id, employee_id, scheduled_at, route_order, geo_tag, signboard_photo, confirmed_by, completed_at.
- **AuditEntry:** id, merchant_id, ts, actor (`agent`|`llm`|`policy`|`rules_engine`|`human:<name>`|`system`), action, payload (JSON), prev_hash, hash. Append-only; `hash = sha256(prev_hash + canonical_json(entry))`. Provide `verify_chain()`.
- **ReviewCase:** merchant_id, reason, evidence, status, decided_by, decision, note.

## Rules engine (deterministic)

`rules_config.yaml` defines requirements per route. Header comment: "Configured to the team's reading of RBI PA Directions 2025, Para 13. Owned by compliance; not legal advice."

- `SMALL_MERCHANT` (turnover ≤ ₹40 lakh and not in CKYCR): `PAN_OR_FORM60_VERIFIED`, `OVD_COLLECTED`, `NAME_MATCH`, `CPV_DONE`, `NO_OPEN_RISK_FLAG`.
- `CKYCR` (record found in CKYCR): `CKYCR_RECORD_VERIFIED`, `NAME_MATCH`, `CPV_DONE`, `NO_OPEN_RISK_FLAG`.
- `FULL_CDD` (turnover > ₹40 lakh): out of prototype scope → always route to human review with reason "full due diligence required".

`evaluate(merchant_id) -> {route, results: [{requirement, passed, evidence_ref, checked_at}], compliant: bool}`. Only when `compliant` is true may the QR status change to `LIVE`.

## Agent behaviour (what judges must see)

- **Decide:** at each step the LLM proposes the next action from an allowed list (`SEND_WHATSAPP`, `PLAY_SOUNDBOX_PROMPT`, `REQUEST_DOCUMENT`, `VERIFY_DOCUMENT`, `SCHEDULE_VISIT`, `WAIT`, `ESCALATE`, `RUN_COMPLIANCE`) with a one-line reason. `policy.py` accepts it if valid for the current state, else overrides. The UI shows "LLM proposed → policy accepted/overrode".
- **Recover:** a rejected document triggers a specific fix message in Hindi; offer Form 60 if the shopkeeper says they have no PAN.
- **Retry:** no reply → retry after a (simulated) delay, then switch channel: Soundbox → WhatsApp → IVR → field visit. Track attempts per channel.
- **Escalate:** mule-risk score above threshold, document confidence < 0.8 after 2 attempts, name mismatch, dispute, or FULL_CDD route → create a ReviewCase; the journey waits for a human decision. The agent never auto-approves an escalated case.
- **State:** journeys are checkpointed per merchant and can be resumed after a server restart.
- Every step writes an AuditEntry.

## Definition of done

- `./run.sh` starts everything; the 5-step finale demo works start to finish in under 4 minutes.
- `DEMO_MODE=replay` runs the full demo with Wi-Fi off.
- `/demo` control page can reset to a clean state in one click.
- `pytest` passes (rules engine, audit chain, scoring, quiet-hour, document checks, end-to-end journey).
- No real personal data anywhere.
